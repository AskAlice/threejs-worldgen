## Agent Brief

**Category:** enhancement
**Summary:** Run the #33 erosion solver live at runtime on bounded maps, driven by weather, with the terrain updating as it erodes.

**Current behavior:**
Once #33 lands, erosion can be baked and stepped (`step(dt)`), but nothing runs it live or feeds the terrain incrementally.

**Desired behavior:**
- A live mode steps the solver every frame within a time budget, at lower resolution than the bake.
- Rain comes from threejs-weathering's weather state (rain intensity and its spatial distribution).
- The visible terrain updates incrementally: only changed regions are re-uploaded or rebuilt, using the existing region-limited terrain invalidation.
- Water depth is exposed so threejs-water can draw running water and floods over the eroding terrain.
- Live mode can be paused, and its state can be serialised so a session resumes identically (deterministic stepping).

**Key interfaces:**
- A live-mode option or controller on the erosion solver (for example `mode: 'live'` with `budgetMs`, `resolution`, `rainSource`).
- Terrain region invalidation from a changed-region bounding box each frame.
- A water depth field (texture or grid) that the water package can sample.

**Acceptance criteria:**
- [ ] Live mode holds 60 fps at 1280×720 on a typical WebGPU laptop with the default budget.
- [ ] Turning heavy rain on visibly carves channels within about 30 s of simulated time, and stopping rain stops erosion.
- [ ] The same seed and inputs replayed give the same eroded result (state hash at step N).
- [ ] Only dirty terrain regions rebuild; the profiler shows no full-terrain rebuilds per frame.

**Out of scope:**
- Erosion on infinite or streamed worlds.
- Learned or neural acceleration (separate spike).
